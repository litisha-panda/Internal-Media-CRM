## Background: Why these errors exist

`lib/db` and `lib/integrations-anthropic-ai` are TypeScript composite projects (`"composite": true` in their `tsconfig.json`). This means `api-server` resolves them through their compiled declaration files in `dist/`, not their `src/` directly. Both `dist/` folders are **stale** — they were compiled at an earlier point in time before several schema tables were added. This is the cause of 6 of the 8 errors. The remaining 2 errors are source-code type annotation issues.

## ROOT CAUSE 3 of 3 — Two source-code type annotation bugs (fixes 2 errors)

These two errors are actual source code mistakes — not build artifacts. Fix them in the order listed.

### Fix A — `deals.ts` line 238: local type annotation narrower than actual return type

**File:** `artifacts/api-server/src/routes/deals.ts`

**Error:** `deals.ts(240,7)`: Type `'{ repId: number | null; ... }'` is not assignable to type `'{ repId: number; ... }'`

**Root cause:** Around line 238 (inside the `POST /api/client-accounts` handler), `owner` is declared with a manually-written narrow type:
```typescript
let owner: { repId: number; region: string; name: string };
```

But `resolveOwnership()` returns `ResolvedOwner` which has `repId: number | null`. The first POST handler in the same file (around line 70) correctly uses `Awaited<ReturnType<typeof resolveOwnership>>` — the second handler does not.

**Fix:** Change the type annotation at line 238 to match the first handler:
```typescript
// BEFORE:
let owner: { repId: number; region: string; name: string };

// AFTER:
let owner: Awaited<ReturnType<typeof resolveOwnership>>;
```

Do not change anything else in this block. The `resolveOwnership` function is already imported at the top of the file — no import change needed.

---

### Fix B — `meetings.ts` lines 269 and 356: Express 5 `req.params` typing

**File:** `artifacts/api-server/src/routes/meetings.ts`

**Error at lines ~269 and ~356:** Type `'string | string[]'` is not assignable to type `'string | null | undefined'`

**Root cause:** `api-server` uses Express 5 with `@types/express@5`. In Express 5's type definitions, `req.params["key"]` returns `string | string[]` rather than `string`. The variable `meetingId` is declared as `const meetingId = req.params["id"]!` in two handlers. This value is then passed to `entityId` in the `void logActivity({...})` call, but `ActivityParams.entityId` expects `string | null | undefined` — not `string | string[]`.

There are exactly two affected `meetingId` declarations — find them by looking for `const meetingId = req.params["id"]!` in the file. There are two of them (one in the PATCH handler, one in the POST /:id/log handler).

**Fix — change both declarations to add a `String()` cast:**
```typescript
// BEFORE (appears twice in the file):
const meetingId = req.params["id"]!;

// AFTER (apply to both occurrences):
const meetingId = String(req.params["id"]);
```

`String()` safely coerces `string | string[]` to `string`. If the param is an array, it will comma-join — but Express route params are never arrays for named segments like `:id`, so this is safe. Do not change any other `req.params` usage in the file.
