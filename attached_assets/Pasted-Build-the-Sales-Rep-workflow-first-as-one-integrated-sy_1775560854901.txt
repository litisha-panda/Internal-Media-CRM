Build the Sales Rep workflow first as one integrated system.

Do not treat UI, backend, database, and triggers as separate tasks.
Build them as one connected workflow.

==================================================
PRODUCT GOAL
==================================================

This is not a generic CRM.

This is a Sales Discipline + Execution + Revenue Control System.

For Sales Rep, the journey must be:

FIRST LOGIN:
Setup Wizard → Submit for approval

NORMAL LOGIN:
Dashboard → My Plan → Revenue Log / Internal Requests / Tasks / HR Reports

The system must be strict, structured, and audit-friendly.

==================================================
1. SALES REP SIDEBAR
==================================================

Sales Rep should see only these tabs, in this exact order:

1. Dashboard
2. My Plan
3. Revenue Log
4. Internal Requests
5. Tasks
6. HR Reports

Hide / disable for Sales Rep:
- Revenue Tracker
- Pipeline tab (if it is actually revenue tracker)
- War Room
- By Region
- All Sales Reps
- Access Management
- Platform Config
- leadership dashboards

==================================================
2. FIRST-TIME SETUP WIZARD
==================================================

On first login only, before normal usage, show a mandatory Setup Wizard.

Before the wizard starts, show a short guided tour:
- Dashboard = target, achieved, shortfall, alerts
- My Plan = where meetings are planned and logged
- Revenue Log = where revenue is entered when RO comes
- Internal Requests = what I have asked from others
- Tasks = what I need to do
- HR Reports = attendance / absence / exceptions

Wizard steps:

STEP 1 — PROFILE
Fields:
- Region (dropdown)
- Reporting Manager (dropdown, filtered appropriately)

STEP 2 — TARGET SETUP
Rep enters target in this exact format:

Agency > Client > Brand > Q1 > Q2 > Q3 > Q4 > Annual

Rules:
- Annual = auto-sum of Q1+Q2+Q3+Q4
- Agency can be dropdown or manually added
- Client can be dropdown or manually added
- Brand can be dropdown or manually added

STEP 3 — IMPORT / SYNC
Allow:
- sync / import clients
- bulk import target allocations
- bulk import achieved so far

STEP 4 — REVIEW & SUBMIT
Show:
- Region
- Manager
- all Agency/Client/Brand rows
- quarterly totals
- annual total
- achieved imported so far

SUBMISSION RULES:
- Once submitted → goes into approval workflow
- If approved → locked
- If rejected → editable and resubmittable

==================================================
3. TARGET APPROVAL WORKFLOW
==================================================

Approval chain must be:

RH → NSH → Strategy → CRO

After CRO approval:
- target becomes locked
- rep cannot edit

If rejected at any stage:
- rep can edit and resubmit

==================================================
4. DASHBOARD
==================================================

After setup is complete, Sales Rep must always land on Dashboard.

Dashboard should show:

A. PERFORMANCE SUMMARY
- Annual Target
- Quarter Target
- Achieved
- Shortfall

B. ALERTS / STATUS
- Pending Tasks
- Pending Internal Requests
- Missed HR compliance
- target approval status if pending/rejected

C. QUICK ACTIONS
- Go to My Plan
- Log Revenue
- View Tasks
- View Internal Requests

Important:
- Do not show planning forms here
- Do not show target entry forms here
- Dashboard is summary + alerts + quick actions only

==================================================
5. MY PLAN
==================================================

My Plan is ONLY for planning and logging meetings.
Do not show target summary here.

My Plan should contain:

A. TODAY
List today’s meetings with:
- Type: PR / Actionable
- Agency
- Client
- Brand
- Person
- Time
- Mode
- Status: Planned / Logged / Missed

Actions:
- Log Touchpoint
- Edit
- Cancel

B. TOMORROW
List tomorrow’s meetings with:
- Add Meeting
- Edit
- Delete

C. COMPLIANCE INDICATOR
Show clearly:
- Logged today? Yes / No
- Planned tomorrow? Yes / No
- Compliance status

==================================================
6. DAILY COMPLIANCE RULE
==================================================

This is mandatory.

FIRST DAY OF USE:
Rep must:
- schedule meetings for today
- schedule meetings for tomorrow
- log today

SECOND DAY ONWARDS:
Rep must:
- log today
- schedule tomorrow

If the rep misses even one required action by 11:30 PM IST:
- mark absent / non-compliant

This must reflect in HR Reports.

==================================================
7. SCHEDULE MEETING FLOW
==================================================

When rep clicks Add Meeting, first ask:

- PR Meeting
- Actionable Meeting

------------------------------------------
7A. PR MEETING
------------------------------------------

If PR Meeting, only ask:
- Agency
- Client
- Who are you meeting?
- Time
- Contact number

Then save.
No downstream action logic.

------------------------------------------
7B. ACTIONABLE MEETING
------------------------------------------

If Actionable Meeting, ask in this order:

1. Agency
- dropdown first
- if not available, allow manual entry
- if client has no agency, allow Agency = NA

2. Client
- if agency selected from dropdown, show clients mapped to that agency
- if client is not mapped to that agency or has no agency, allow manual entry

3. Brand / Product
- if client exists in dropdown, show brands mapped to that client
- if not available, allow manual entry

4. Who is the representative being met?

5. Contact number
Rules:
- validate properly
- support country code
- do not allow invalid unlimited digits

6. Mode
- Physical
- Online
- Phone Call

7. Actionable Type
Use this exact dropdown:
- Pitch / Introduction
- Proposal discussion
- Negotiation / Pricing
- Closure / Conversion
- Follow-up
- Relationship + business discussion
- Collection / payment follow-up
- Renewal / repeat business

8. Agenda
Free text

9. Date and Time

==================================================
8. LOG TOUCHPOINT FLOW
==================================================

Logging should begin from a scheduled meeting wherever possible.

When user clicks Log Touchpoint from Today, auto-fill:
- Agency
- Client
- Brand
- Person
- Time
- Mode
- Meeting type
- PR / Actionable type

Do not ask the rep to re-enter these.

Log Touchpoint should ask only:

1. Discussion
Free text

2. Feedback
Use this exact dropdown:
- Interested – proceed
- Needs proposal
- Price concern
- Budget not available
- Decision pending
- Follow up later
- Not interested
- Converted (mail confirmed)
- Closed – no opportunity

3. Stage
Use:
- Prospect
- In Discussion
- Negotiation
- Mail Confirmed
- RO Received
- Lost

4. Do I need anything from any other department?
If Yes, show:
- What is needed? (fixed dropdown)
- Who is it needed from? (fixed dropdown)
- By when? (calendar)

5. Is there a follow-up?
If Yes:
- next meeting date

CONDITIONAL RULES:
- If stage = Mail Confirmed or RO Received, do not show “what do you need / who do you need from”
- If stage = RO Received, prompt rep to log revenue
- If status is closed / no opportunity, no follow-up required

Rep must also be allowed to schedule and log an impromptu meeting for today even if it was not pre-planned.

==================================================
9. ACTION REQUIRED / SUPPORT TRIGGERS
==================================================

If rep enters:
- what is needed
- who it is needed from
- by when

then on submit system must automatically create:

1. A Task for the assignee
2. An Internal Request for the raiser
3. A calendar reminder / schedule for the raiser
4. A calendar reminder / schedule for the assignee

If “What is needed” = Approval,
also create a trigger in the Approval tab of the person it is assigned to.

Multiple action items per touchpoint are allowed.

==================================================
10. TASK ESCALATION
==================================================

If task is not completed by due date:
- escalate to RH
- after 12 hours, escalate to NSH
- after 12 more hours, escalate to CRO

Exact chain:
RH → NSH → CRO

==================================================
11. REVENUE LOG
==================================================

There is no separate Revenue Tracker for now.
Disable that module for Sales Rep.

Revenue Log must remain.

Whenever stage = RO Received:
- prompt rep to log revenue

Revenue Log fields:
- agency

- brand
- RO reference / number
- revenue amount
- date

- notes

Rule:
- Achieved on Dashboard must update from Revenue Log

Show all requests the rep has raised:

13. TASKS TAB
==================================================

Show:

Show:

==================================================
16. BACKEND RULES
==================================================

1. All dropdowns fetch from master tables
2. All user actions write into transaction tables
3. Dashboard numbers come from backend KPI calculations
4. No frontend-only truth for core workflows
5. No generic JSON blobs for core accounting/workflow entities
6. All approvals and escalations must be stored as status transitions
7. Revenue is immutable except for reversal handling
8. My Plan, Tasks, Internal Requests, HR must all read from backend data

==================================================

==================================================

Build / keep APIs for:
- setup/profile
- targets submit / approve / reject / read allocations
- meetings create / update / list
- touchpoints log
- action items create / escalate
- tasks create / status / reschedule / reassign / note
- internal requests create / accept / resolve / reject / withdraw / note
- approvals create / resolve
- revenue create / list / aggregate
- HR compliance daily job / read
- HR exception create / approve / reject
- dashboard KPI endpoints
