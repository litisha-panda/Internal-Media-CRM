OTV CRM — Rebuild Prompt
Read everything before writing a single line of code. The most important principle: every screen reads from the same data. No isolated tabs. No separate arrays. One change anywhere updates everything everywhere.

What this app is
An internal sales operating system for Odisha Television Network. Two companies:
	∙	Odisha Television Ltd — channels: OTV, Odisha TV
	∙	Tarang Broadcasting Company Ltd — channels: Tarang TV, Tarang Music, Alankar, Prarthana
Stack: React + Vite frontend, Express + PostgreSQL backend, Drizzle ORM, usePersistedState for all state, Claude proxy at port 8080.

The one rule everything depends on

ACHIEVED = sum of RevenueEntries only.
Never from deal stages. Never from deal amounts.
One entry in Revenue Log = one credit to ACHIEVED.
Nothing else. Ever.


Every screen — rep view, manager view, leaderboard, every tab — reads from this same calculation. This is what makes everything talk to each other.

The four numbers — one shared function
Build one function calcNumbers(repIds, fiscalYear, quarter). Call it from every screen. Never inline the calculation.

ACHIEVED   = sum of RevenueEntries where repId in repIds AND fiscalYear matches
COMMITTED  = sum of ClientAccount.annualTarget where currentStage = "Mail Confirmed"
IN PLAY    = sum of ClientAccount.annualTarget where currentStage in ["In Discussion", "Negotiation"]
SHORTFALL  = totalTarget - ACHIEVED - COMMITTED - IN PLAY


When revenue is logged: ACHIEVED goes up, COMMITTED goes down (that account moves to RO Received). Everything recalculates immediately. No refresh.

Deal stages — how they work
Stage changes in ONE place only: the touchpoint log form when touchpointType = Deal Meeting. No dropdowns anywhere else.

Prospect      → no pipeline impact, no escalation
In Discussion → enters IN PLAY
Negotiation   → stays IN PLAY, higher urgency
Mail Confirmed → moves to COMMITTED, hide action items, show RO reminder
RO Received   → set automatically when revenue logged, moves to ACHIEVED
Lost          → mandatory loss reason, removed from all calculations


The touchpoint log form
The most important form. Fields in order:
	1.	Client — Zoho search, required
	2.	Touchpoint type — Relationship or Deal Meeting toggle
	3.	If Deal Meeting — Stage dropdown (Prospect/In Discussion/Negotiation/Mail Confirmed/Lost)
	∙	If Lost → loss reason field, mandatory
	∙	If Mail Confirmed → hide action items, show “Waiting for RO? Set a reminder (3/5/7 days)”
	4.	Contact — name, designation, level
	5.	What happened — required
	6.	Client feedback — optional
	7.	Action items — shown ONLY for Prospect/In Discussion/Negotiation. Hidden for everything else.
On submit: clientAccount thread updated, stage updated, lastDealMeetingDate updated (if Deal Meeting), all four numbers recalculate everywhere, meeting card turns green, action items route automatically.

Action item routing

Approval needed    → assignee's Approvals tab + My Tasks. SLA 48h. Breach → Escalations.
Document needed    → assignee's My Tasks. SLA 48h. Breach → Escalations.
Attend a meeting   → assignee's My Plan as unscheduled request. SLA 48h to confirm.
Introduction needed → assignee's My Tasks. No SLA.
Flag for follow-up → Legal or Finance My Tasks only.
Self               → rep's My Tasks only. No notification to anyone.


Missed due date on any type → Escalations tab of assignee → manager War Room “Overdue in my team.”
Task title format always: [Action type] — [Client] — [Details] — by [Date] — from [Rep]

My Plan
Priority order every morning:
	1.	At Risk cards (no deal meeting 7+ days on active account) — red, highest value first
	2.	Action items due today
	3.	Today’s meetings — grey=upcoming, red pulsing=overdue unlogged, green=logged
	4.	Tomorrow’s meetings
After logging: inline prompt showing next action. Never navigate away automatically.
11:30 PM rule: countdown grows from subtle → amber (6pm) → red banner (9pm) → fullscreen block (11pm). Must log or confirm “nothing to log.” Else: marked absent.

Revenue Log
Second item in sidebar. Always visible.
Fields: Client (dropdown of approved accounts), Amount, Invoice Ref (required), Date, Deal Type, Notes.
On submit: RevenueEntry created → clientAccount.currentStage = RO Received → calcNumbers() runs everywhere immediately → screen shows “₹X logged for [Client]. Fiscal year total: ₹Y.”
Edit button on each row. Rep and Admin only. Every edit logged with who/when/old amount.

Client account thread
Click any client anywhere in the app → opens full thread.
Top: current stage, days since last deal meeting, four numbers for this client, open action items.
Thread (newest first): every touchpoint — date, type badge (Relationship/Deal Meeting), contact, stage change, what happened, action items raised, revenue logged.
Read only. Add new touchpoints or “+ Add Action Item” to past touchpoints only.

Escalation engine (background, automatic)
	1.	No deal meeting 7 days → At Risk on rep’s My Plan. Day 10 → RH War Room. Day 14 → RH task.
	2.	4+ deal meetings same client in 30 days, no stage movement → RH War Room alert.
	3.	Under 15 touchpoints in a month → RH War Room alert last day of month.
	4.	Any task/approval past due date → Escalations tab of assignee → manager notified.
All thresholds configurable in Admin System Config.

Admin System Config
	∙	Platform State: Pre-launch / Live. When Pre-launch: reps see holding screen only.
	∙	Inactivity thresholds: 7 / 10 / 14 days (configurable)
	∙	Minimum meetings per month: 15 (configurable)
	∙	SLA hours: RH 48h, NSH 48h, Legal 72h, others 48h
	∙	Approval thresholds by deal value

Zoho integration
Server-side only. Never expose credentials to browser.
GET /api/zoho/clients?q= — searches Zoho Accounts, returns name + zohoAccountId
Auto token refresh using ZOHO_REFRESH_TOKEN from Replit Secrets.
ZohoSearchInput component: rep types 3+ chars, dropdown shows Zoho results, rep selects. Stores clientName + zohoAccountId. If Zoho down: free text with warning.
Two base URLs:
	∙	https://crmsandbox.zoho.in/crm/v2 — all lookups
	∙	https://crmsandbox.zoho.in/crm/broadcast/v2 — deal pushes only
